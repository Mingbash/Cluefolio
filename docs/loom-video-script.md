# Cluefolio Loom 演示脚本

目标时长约 3 分 40 秒。语气像给朋友展示自己做的小工具：第一人称、正常语速。录屏以真实可展示的笔记和实际构建结果为准。画面中的等待可剪辑，字幕标明“已剪去处理等待时间”。

| 时间 | 录屏画面与动作 | 口播文案 |
| --- | --- | --- |
| 0:00–0:35 | 打开小红书收藏夹，滚过几篇曾经收藏的干货；切到工作文档中的 LinkedIn 运营待办。 | “我刷小红书，经常碰到博主讲得特别实在。先收藏，想着以后做项目肯定用得上。结果真要做事的时候，往往想不起是哪篇；就算记得，也懒得回收藏夹一条条翻。很多内容看过就过去了，根本没进入我的工作流程。” |
| 0:35–1:17 | 一屏展示一份从笔记直接整理的长 Skill；一屏展示普通搜索返回的原文片段；停在两条发布日期不同、说法不同的建议上。不要使用其他产品的商标或伪造回答。 | “我试过把博主的笔记直接写进 Skill。写短了，判断条件和例外容易丢；写长了，Agent 每次都得翻一大段。把原文放进检索库，相关段落是找得到，但它不会自动替我分清：哪些是博主自己的方法，哪些是他引用来的事实。让模型临时搜索也能解决一部分问题，只是每次搜到的材料会变。在变化快的领域，去年的平台规则和操作建议，如果今年照着做，可能比暂时没有建议更麻烦。” |
| 1:17–1:45 | 展示[立正老师的 Open Context 仓库](https://github.com/sunyuzheng/lizheng-open-context)中的 `corpus/`、`context/` 与来源目录；随后切到 Cluefolio 项目页。 | “后来我看到立正老师开源的 Open Context。他把原始资料、来源关系和整理后的判断分开保存，还留着日期和视频时间码。我很喜欢这个思路，于是做了 Cluefolio。我叫它‘Context 淘金盆’：从我挑过的材料里淘出值得反复使用的原则，也把原始证据留在旁边。” |
| 1:45–2:16 | 用一篇图文、一篇视频作为实际样本，展示图片页码、口播时间码、上游文章、博主贡献、原则卡和日期；画面不要出现私有令牌。 | “它能处理文字、纯图片和视频笔记。找到上游原文时，原文和博主自己的解释分别保留；找不到时也会留下查源范围。整理出来的 Context 会写清原则适用在什么情况下。数据、价格、平台玩法这类容易变的东西，会带着原始日期，回答当前怎么做之前再查一次。我不想让一句旧建议悄悄变成今天的标准答案。” |
| 2:16–3:05 | 新建项目，命名“LinkedIn 账号运营”；导入事先获准展示的真实小红书笔记链接；勾选几篇；点击“开始构建”；剪辑跳过等待，展示项目进度和产物。 | “演示一下。我新建一个‘LinkedIn 账号运营’项目，贴进几篇讲主页定位、内容选题和获客的笔记，勾出我想参考的。点开始构建后，它逐篇读取，处理图文和视频，再查相关来源。碰到登录验证或者材料缺失，它会停下来告诉我是哪一步；处理好的部分会保留。” |
| 3:05–3:34 | 在 ChatGPT Desktop 的本地 Agent 任务聊天中选择这个 Context 自动生成的 Skill，输入演示问题；展示回答中一条长期原则、一条需按当下情况核对的建议，以及可打开的出处。 | “构建好以后，每个 Context 都有一个轻量的 Skill 当入口。我在 Agent 的任务聊天里选它，然后问：‘我做 B2B 服务，LinkedIn 账号前四周怎么验证选题？’回答会用整理出的原则和笔记依据；涉及 LinkedIn 现在的规则，会提醒我核对最新来源。需要的话，我还能回看对应图片或视频段落。” |
| 3:34–3:50 | 打开 [Cluefolio GitHub 仓库](https://github.com/Mingbash/Cluefolio)，指向 README 顶部给 Agent 的安装指令；结尾停在仓库地址。 | “想试的话，把这个 GitHub 仓库发给你的 Agent，让它先检查电脑缺什么依赖，再帮你安装。我们验收的是 Mac 上 ChatGPT Desktop 里的 Codex 本地任务；其他 Agent 可以照配置探索。项目开源，欢迎把实际用到的问题带回来。” |

## 录制前的真实性检查

- LinkedIn 演示须用有权展示的真实笔记；若只有模拟资料，画面明确标“演示数据”，口播相应改成“这里用模拟笔记展示流程”。不要把融资 Context 冒充 LinkedIn Context。
- 录制“每个 Context 自动安装 Skill”和“时效提示”镜头前，先确认这两项已在实际版本验收通过。若尚未完成，删去对应镜头与承诺，保留现有检索演示。
- 截屏前隐藏分享令牌、浏览器身份、私有路径和原文媒体下载地址；演示答案须来自当次实际运行，不预写成产品返回。
- 引用立正项目时使用其[原仓库](https://github.com/sunyuzheng/lizheng-open-context)；说明“思路启发”，不暗示 Cluefolio 使用了其代码或得到其背书。
